# 0002. Доска MR рендерится rich-сообщением с Markdown-таблицами

Дата: 2026-10-29. Статус: принято.

## Контекст

Доска MR (ADR 0001) отправляется plain text без `parse_mode`: нет гиперссылок на MR, нет форматирования, длинные титулы съедают место, строки трудно сравнивать глазами. Лимит обычного сообщения 4096 символов заставлял держать трункацию «…и ещё N MR».

Bot API 10.1 добавил Rich Messages (проверено 2026-10-29 по официальному changelog и справочнике API): `sendRichMessage` в группы и супергруппы, Markdown-режим совместим с GitHub Flavored Markdown — таблицы с выравниванием, заголовки, списки, детали; `editMessageText` принимает `rich_message`, то есть закреплённое сообщение можно по-прежнему редактировать на месте. Лимиты: 32768 символов, 500 блоков (строки таблицы считаются блоками), 20 колонок на таблицу.

## Решение

Доска становится rich-сообщением: секции — таблицы Markdown, reference каждого MR — гиперссылка (`web_url` из GitLab API), титул обрезается до 48 символов. Три вида группировки строк («по мячам», «по ревьюверу», «по проекту») — per-channel настройка, владелец меняет кнопкой-циклом в меню канала. Трункация `fit()` удаляется: 32k символов покрывают всю команду.

## Последствия

- Клиенты без поддержки Rich Messages могут не отрендерить доску. Fallback-флаг не делаем: команда сидит в свежих клиентах; если появятся жалобы — добавим откат на `parse_mode: HTML` отдельным изменением.
- Существующий закреплённый plain-text пин мигрируется: бот снимает старый пин, отправляет rich-сообщение и пинит его заново.
- `editMessageText` с `rich_message` закрывает обновление на месте; диф-логика «не менялось — не редактируем» сохраняется.
- Строки таблиц считаются блоками, лимит 500 блоков ≈ сотни MR — для команды запас избыточный.
- В ячейках таблиц надо экранировать `|` в титулах MR.
