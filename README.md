# MeetHub

### Ежедневный Telegram-хаб для команд и сообществ

Помогает управлять публикациями в каналах, расписанием встреч и связанными отчётами — без привязки к одному продукту.

## Возможности

- Подключение Telegram-канала и группы обсуждений с проверкой прав.
- Регулярные публикации по пяти-полевому cron-расписанию и разовый перенос ближайшей публикации.
- Формирование публикации со ссылкой на встречу; при включённой настройке — выбор ведущего из отчётов.
- Доставка сводки в связанную группу и уведомления владельцу о сбоях.
- Хранение настроек, расписания, публикаций и состояния бота в PostgreSQL.

## Быстрый старт

Нужны Docker Compose и Telegram-бот, созданный через [@BotFather](https://t.me/BotFather). Узнайте свой Telegram ID для `TELEGRAM_OWNER_ID`.

```sh
git clone https://github.com/passwordhash/meethub-bot.git
cd meethub-bot
cp .env.example .env
```

Заполните `.env`, затем запустите приложение:

```sh
docker compose up -d --build
```

Compose поднимет PostgreSQL, применит миграции и запустит бота. Логи: `docker compose logs -f bot`.

Для локального запуска без Docker: установите Go 1.23+ и PostgreSQL, задайте переменные из `.env` в shell, затем выполните `make migrate` и `make run`.

## Настройка бота

1. Напишите боту `/start` от имени владельца.
2. В личном чате отправьте `/connect <ID канала>`. Вы должны быть администратором канала; боту нужны права администратора и публикации. Бот также должен иметь право отправлять сообщения в связанной группе.
3. Настройте расписание через меню или команду `/daily-schedule <ID канала> "30 9 * * 1,3,5"`.

Cron использует пять полей; понедельник — `1`, воскресенье — `0`. Время расписания — UTC+3. Другие команды:

- `/daily-schedule <ID канала> lead on|off` — включить или выключить выбор ведущего.
- `/move <ID канала> <YYYY-MM-DD> <HH:MM>` — перенести ближайшую публикацию на указанное время (UTC+3).

Privacy mode Telegram надёжно не раскрывает сообщения группы боту: отключите его через BotFather и заново добавьте бота в группу обсуждений.

## Публикация и данные

В публикацию входят дата, `MEETING_URL`, время встречи 10:00 (UTC+3) и, если настройка выбора ведущего включена и доступны отчёты, строка с ведущим. Расписание проверяется каждые 15 секунд; права повторно проверяются непосредственно перед отправкой. Сводка публикуется в связанной группе ответом на автопересланное сообщение канала.

Миграции намеренно не содержат `Down`: откат мог бы удалить пользовательские данные и настройки. Резервные копии автоматически не создаются — обеспечьте их самостоятельно. Отключение привязки канала пока не реализовано.

## Разработка и деплой

```sh
go test ./...
make lint
```

`./deploy.sh` обновляет настроенный сервер по SSH и выполняет `docker compose up -d --build`. По умолчанию используется узел `srv-31-169-124-108`; переопределите его переменной `DEPLOY_SERVER`. На сервере должны существовать рабочая копия в `/opt/cascade-hub-bot` и настроенный `.env`. Деплой не создаёт резервные копии.

## Конфигурация

Скопируйте `.env.example` в `.env` и задайте значения. `MEETING_URL` должен быть HTTPS-ссылкой; `POSTGRES_HOST` для локального запуска — `localhost`, Compose сам использует адрес `db`.

Не коммитьте `.env` и не передавайте реальные секреты в issue или логи.
