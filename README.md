# MeetHub

### Ежедневный Telegram-хаб для команд и сообществ

Помогает управлять публикациями в каналах, расписанием встреч и связанными отчётами — без привязки к одному продукту.

## Возможности

- Подключение Telegram-канала и группы обсуждений с проверкой прав.
- Недельная сетка дейликов: для каждого дня недели своё время начала (UTC+3), не более одного дейлика в день, и общее упреждение, за которое до дейлика выходит пост.
- Формирование публикации со ссылкой на встречу и фактическим временем дейлика; при включённой настройке — выбор ведущего из отчётов.
- Доставка сводки в связанную группу и уведомления владельцу о сбоях.
- Хранение настроек, расписания, публикаций и состояния бота в PostgreSQL.

## Быстрый старт

Нужны Docker Compose и Telegram-бот, созданный через [@BotFather](https://t.me/BotFather). Узнайте свой Telegram ID для `TELEGRAM_OWNER_ID`.

```sh
git clone https://github.com/passwordhash/meethub-bot.git
cd meethub-bot
cp .env.example .env
```

Заполните `.env`, затем запустите приложение:

```sh
docker compose up -d --build
```

Compose поднимет PostgreSQL, применит миграции и запустит бота. Логи: `docker compose logs -f bot`.

Для локального запуска без Docker: установите Go 1.23+ и PostgreSQL, задайте переменные из `.env` в shell, затем выполните `make migrate` и `make run`.

## Настройка бота

1. Напишите боту `/start` от имени владельца.
2. В личном чате отправьте `/connect <ID канала>`. Вы должны быть администратором канала; боту нужны права администратора и публикации. Бот также должен иметь право отправлять сообщения в связанной группе.
3. Снова отправьте `/start`, выберите канал и настройте его на одном экране:
   - кнопка дня недели: бот попросит время дейлика в формате `ЧЧ:ММ` (UTC+3, любая минута); там же можно убрать день или отменить ввод;
   - «Пост за N мин»: упреждение 15, 30, 60, 120 минут или своё целое число от 0 до 1439; пост может выйти накануне дейлика;
   - «Ведущий»: включает или выключает выбор ведущего из отчётов.
   - «Игнор-лист»: Telegram ID пользователей, чьи сообщения бот не считает отчётами: они не попадают в сводку и выбор ведущего. ID добавляется кнопкой «Добавить», удаляется нажатием на него. Отчёт, сохранённый до добавления в список, остаётся в текущей сводке.

Команды `/daily-schedule` и `/move` не поддерживаются, остались только `/start` и `/connect`. Любая команда отменяет ожидание ввода.

Privacy mode Telegram надёжно не раскрывает сообщения группы боту: отключите его через BotFather и заново добавьте бота в группу обсуждений.

## Публикация и данные

В публикацию входят день недели и дата дейлика, `MEETING_URL`, фактическое время встречи (UTC+3) и, если настройка выбора ведущего включена и доступны отчёты, строка с ведущим. Время поста вычисляется как время дейлика минус упреждение. Расписание проверяется каждые 15 секунд: пост, чьё время наступило, выходит, пока дейлик не начался; после начала неопубликованный дейлик помечается пропущенным, и владелец получает уведомление. На одну дату дейлика в канале выходит один пост: если он уже вышел, изменение времени этого дня подействует со следующей недели. Права повторно проверяются непосредственно перед отправкой. Сводка публикуется в связанной группе ответом на автопересланное сообщение канала.

Прежние cron-расписания вида `М Ч * * ДНИ` при обновлении переносятся в сетку так, чтобы посты выходили в прежнее время; остальные сбрасываются, и бот один раз сообщает об этом владельцу.

Миграции намеренно не содержат `Down`: откат мог бы удалить пользовательские данные и настройки. Резервные копии автоматически не создаются — обеспечьте их самостоятельно. Отключение привязки канала пока не реализовано.

## Разработка и деплой

```sh
go test ./...
make lint
```

Для деплоя укажите SSH-адрес сервера и путь к клону репозитория на нём:

```sh
DEPLOY_SERVER=user@server DEPLOY_PATH=/path/to/repository ./deploy.sh
```

На сервере должны быть настроены SSH-доступ и `.env`. Скрипт обновит рабочую копию и выполнит `docker compose up -d --build`. Резервные копии не создаются.

## Конфигурация

Скопируйте `.env.example` в `.env` и задайте значения. `MEETING_URL` должен быть HTTPS-ссылкой; `POSTGRES_HOST` для локального запуска — `localhost`, Compose сам использует адрес `db`.

Не коммитьте `.env` и не передавайте реальные секреты в issue или логи.
