# Cascade daily bot — этап 1

Требуются Go, PostgreSQL и goose через Go modules. Скопируйте `.env.example` в локальный `.env` (он игнорируется Git), затем загрузите значения в текущий shell командой `set -a; . ./.env; set +a`. Локальные команды требуют `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OWNER_ID`, `MEETING_URL` и раздельные `POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_DATABASE`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_SSLMODE`; затем выполните `make migrate` и `make run`. Пароль мигратора передаётся через окружение, не через аргументы процесса. Бот подключается только к Telegram Bot API исходящими HTTPS-запросами и хранит Telegram ID каналов/групп в Postgres. Telegram chat/user IDs — внешние числовые `int64`, а не внутренние UUID; здесь они являются именно идентификаторами Telegram, UUID-домена не вводятся.

В личном чате от владельца используйте `/connect <числовой ID канала>`. Владелец должен быть администратором канала; бот должен быть администратором с правом публикации в канале и иметь право отправки сообщений в привязанной группе. Связь группы/канала сверяется в обе стороны. Ошибки проверки блокируют запись. Privacy mode Bot API надёжно не раскрывает: вручную отключите его через BotFather и заново добавьте бота в группу обсуждений.

Миграции намеренно не содержат Down: откат удалил бы пользовательские данные/настройки, а резервных копий в MVP нет. Владелец открывает меню кнопок командой `/start`. Кнопка «Расписание» ведёт к выбору канала и вводу пяти-полевого cron-выражения обычным сообщением (например, `30 9 * * 1,3,5`; понедельник=1, воскресенье=0; время UTC+3). Кнопка «Случайный ведущий» показывает подключённые каналы и переключает настройку. Те же действия доступны командами `/daily-schedule <ID канала> "<cron-выражение>"` и `/daily-schedule <ID канала> lead on|off`. Публикация использует шаблон с датой, ссылкой `MEETING_URL`, временем встречи 10:00 UTC+3 и строкой ведущего, если выбор ведущего включён и есть отчёты. Разово перенести ближайший слот можно через `/move <ID канала> <YYYY-MM-DD> <HH:MM>`. Время фиксировано UTC+3. Перенос заменяет первый будущий регулярный слот указанной будущей датой; цель может быть раньше первого слота, но должна строго предшествовать второму будущему регулярному слоту (цель на втором слоте или позже отклоняется). Поэтому перенос не пересекает другой регулярный слот. Повторный `/move` заменяет текущий перенос с теми же ограничениями. При изменении `/daily-schedule` будущий перенос сохраняется, только если он остаётся раньше второго регулярного слота нового расписания; иначе сбрасывается. Регулярные настройки не меняются от `/move`. Планировщик проверяет расписание каждые 15 секунд и повторно проверяет права непосредственно перед публикацией. Сводка доставляется в связанную группу ответом на автопересланную публикацию. Сбои отправляют владельцу краткое уведомление без содержимого отчётов. Отключение привязки не реализовано. Не добавляйте секреты в репозиторий. Бот не логирует Telegram-тексты или токен.

## Compose и деплой

Для локального запуска: `cp .env.example .env`, заполните значения, затем `docker compose up -d --build`; Compose запускает миграции до бота. В Compose адрес PostgreSQL для бота переопределён на `db`; локальный `.env` и `make run` по-прежнему используют `POSTGRES_HOST=localhost`. Укажите `MEETING_URL` как HTTPS URL и реальные настройки только в `.env`.

Деплой: `./deploy.sh` обновляет `/opt/cascade-hub-bot` на SSH-узле `srv-31-169-124-108` через fast-forward pull и `docker compose up -d --build`; серверный `.env` и volume не удаляются. Резервные копии автоматически не создаются: потеря volume/хоста может привести к утрате пользовательских данных.
